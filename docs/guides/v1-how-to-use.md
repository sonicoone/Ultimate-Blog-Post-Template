### ⚙️ Critical Implementation Guidance

-   **Notion/Airtable Conditional Logic Is Mandatory:** Do not use a flat document for briefs. Tier 1 briefs must surface original data upload fields; Tier 3 briefs should hide them. This enforces the tier system at the UI level, not just in documentation.
-   **Automate the Freshness Trigger:** Manual click monitoring does not scale. Configure GA4 custom alerts with Slack/webhook delivery so decay signals arrive proactively. The SLA clock starts when the alert fires, not when someone checks a dashboard.
-   **Legal Sign-Off Must Be System-Enforced:** A checkbox in a doc is insufficient. Build the compliance sign-off as a required CMS metadata field that blocks publication until populated. This converts policy into platform constraint.
-   **AIO Tracking Requires Custom Infrastructure:** No off-the-shelf SEO tool reliably tracks AI Overview citations as of mid-2026. Budget engineering time for the custom tracker script listed in the Q3 2026 roadmap, or contract a vendor offering this capability.
-   **Staging QA Must Be Automated in CI/CD:** Running axe-core manually is error-prone. Integrate it into your deployment pipeline so builds fail automatically on accessibility violations. Human QA should only validate what automation cannot (reading order, embed functionality).
-   **Tool Access = Role Definition:** Map tool permissions to the Owner column. Writers need CMS draft access but not publish; Legal needs metadata field write access but not content editing; DevOps needs staging deploy but not brief database access. Enforce least-privilege to maintain gate integrity.
